# راهنمای بررسی مستقل بستهٔ شواهد

لینک همین ریپو برای دسترسی به مقاله، گزارش، یافته‌ها، کد و فایل‌های خام کافی است.
برای اجرای کنترول‌ها، ریپو را Clone یا از گزینهٔ **Code → Download ZIP** دریافت
و فایل فشرده را باز کنید. دستورها از ریشهٔ ریپو اجرا می‌شوند. هیچ کلید API برای
کنترول شواهد ذخیره‌شده لازم نیست و هیچ درخواست تازه‌ای به مدل فرستاده نمی‌شود.

## کنترول نخست؛ بدون نصب کتابخانهٔ اضافی

با Python 3.11 یا جدیدتر اجرا کنید:

```bash
python rag_security_revision_v2/release/verify_evidence.py
```

این کنترول، هش فایل‌های انتشار و دو انجماد، بازسازی درخواست‌های دقیق، تمام
۲۵۵۹ پاسخ متمایز در سه نوبت، اتصال به ۵۲۰۸ سطر شرایط، مصرف توکن و دفتر هزینه
را تطبیق می‌دهد. همچنان ۱۹۶ سلول خلاصه و ۴۸ شمار انتقال جفتی را مستقل از
ارزیاب اصلی محاسبه و ۲۴۴ فایل مبنای تاریخی را بررسی می‌کند. خروجی باید
`verification: passed` باشد. رسید موقتی بیرون از ریپو ساخته و پاک می‌شود؛ فایل‌های
منتشرشده تغییر نمی‌کنند. این کنترول محاسباتی، داوری معنایی تازه ایجاد نمی‌کند.

## بازتحلیل کامل خروجی‌های ذخیره‌شده

برای تطبیق دقیق محیط انجماد از Python **3.12.14** و نسخه‌های ثبت‌شده استفاده کنید:

```bash
python -m pip install -r rag_security_revision_v2/release/requirements-reanalysis.txt
python rag_security_revision_v2/analysis/analyze_study_c.py --data-root rag_security_revision_v2/data --run-root rag_security_revision_v2/study_c --output reanalysis_local
```

خروجی تازه در `reanalysis_local/` قرار می‌گیرد. آن را با جدول‌های
`rag_security_revision_v2/analysis/study_c/` مقایسه کنید؛ زمان ساخت و مسیرها ممکن
است فرق کند، ولی شمارها و برآوردهای تعریف‌شده باید یکسان باشند. API فقط برای
اجرای یک آزمایش تازه لازم است؛ چنین اجرایی جزو این دستورها نیست.

## محل شواهد و حدود آن

- `rag_security_revision_v2/study_c/`: پاسخ‌های خام، بردارها، زمینه‌ها، درخواست‌ها،
  هش‌ها، دفتر مصرف و رسید تکمیل اجرای واقعی C.
- `rag_security_revision_v2/data/`: snapshot ثابت منبع، پرسش‌ها، اهداکنندگان،
  درج‌های مصنوعی، تصمیم‌های انتخاب و فایل‌های مرجع.
- `rag_security_revision_v2/assistant_review/`: انتخاب نمونهٔ ۷۲موردی و یادداشت‌های
  کمکی منبع‌دار؛ انتساب بررسی دستی نویسنده در سند جاری یافته‌ها مشخص می‌شود.
- `revision/experiment/`: آرشیف مولد B؛ اشکال مرجع و تحلیل‌های پسینی آن در نسخهٔ
  جاری توضیح ارائه شده‌اند و پاسخ‌های قدیمی خاموش جایگزین نشده‌اند.
- `research_phase/` و `final_submission/`: شواهد مراحل پیشین و فایل‌های مبنا.
  دیتا و کد فعلی A موجودند؛ آرشیف دقیق اجرای اصلی ۲۱۸۴۰سطری و تکرار
  ۳۰۱۶سطری بازیابی نشده است. اجرای C جای آن آرشیفها معرفی نمی‌شود.

برخی تعریف‌های آرشیفی ارزیابی در انجماد اولیه هش شده‌اند و در مسیر اصلی حفظ
می‌شوند. نگهداری آن‌ها برای بررسی تمامیت است؛ روش و دامنهٔ جاری تحقیق را مقاله
و گزارش تازه تعیین می‌کنند. تعهد تازه‌ای از وجود فایل آرشیفی نتیجه گرفته نشود.

متن‌های HotpotQA/Wikipedia و snapshot منبع تابع انتساب و شرایط اعلام‌شدهٔ
CC BY-SA 4.0 هستند؛ فایل `data/source_dataset_metadata.json` منشأ را ثبت می‌کند.
درج‌های حمله، ساختگی و صرفاً آزمایشی‌اند و نباید به‌عنوان واقعیت نقل شوند. هیچ
فایل `.env`، کلید API یا محیط مجازی در این انتشار قرار ندارد.
